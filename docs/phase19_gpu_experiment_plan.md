# Phase 19A GPU experiment plan: plain ConvNeXt-T versus the existing CNN baselines (prepared; NOT launched)

Research prototype. Labels are the project's automated weak labels, so every result is descriptive agreement with those labels, not accuracy; no claim is possible without an independent adjudicated reference (Phase 17A protocol, section 5). Nothing here has been run on a GPU.

## Readiness
| Experiment | Ready? | Why |
|---|---|---|
| **D**: plain ConvNeXt-T, ACL + Medial Meniscus, registered seed 201 | **Technically ready; scientifically weak without pretrained weights** | code, tests, driver, bundle and CPU rehearsal done; random initialisation only; pretrained weights need an approval decision |
| **E**: ConvNeXt-T + ROI box pooling | **Not ready (blocked)** | no independent ROI boxes or detector exist; ground-truth boxes do not exist either, so not even an oracle bound can be run; see `phase19_convnext_reproduction.md` |
The driver therefore trains arm D only and records that E was not run. A comparison D versus E must not be launched until an ROI source with recorded provenance is approved.

## Design (fixed before any run)
- Data: the Phase 17A frozen inputs (manifest v0.1.0 `b44de700...`, 1,200-study pool `83a416a0...`, original B0 labels), partition **seed 201** (962 train / 238 validation, hash `b97c2728...`, registry-enforced). Targets ACL and Medial Meniscus; Lateral Meniscus is masked from the loss with reliability weight 0 so that the manifest and splits stay identical to Phase 17A.
  Gold, test and the inspected Phase 16 hold-out are excluded and re-checked; no protected result is used for selection.
- Preprocessing (identical to Phase 17A except resolution): per-slice 1-99 percentile normalisation, nine evenly spaced slices per plane including first and last, bilinear resize to **256 x 256**, plane order Axial / Coronal / Sagittal, one grey channel replicated to three and standardised with (x - 0.45) / 0.225.
- Model D: 29.015 M parameters, drop-path 0.1, no pretrained weights (unless a local ImageNet file with a recorded SHA-256 is approved and attached). Training: AdamW lr 1e-4, weight decay 0.05, cosine with one warm-up epoch, gradient clip 1.0, batch 2 studies (54 slice images), FP16 AMP, 12 epochs, no early stopping, final epoch reported. Recipe is untuned; no search on any validation set.
- Checkpoints (existing resumable format): model, optimizer, scheduler, GradScaler, torch/python/numpy/CUDA/loader RNG, epoch and global step, full config, metrics history, train/validation study IDs, dataset fingerprint (includes manifest hash); written each epoch, resumable at epoch boundaries (resume equality tested on CPU for this model), SHA-256 recorded in the run summary; `last_best.pt` is dropped to save space.
- Controls and context (same validation studies, same labels): metadata-only logistic regression and boosted tree on header features fitted on the same training studies; untrained ConvNeXt-T (ten fixed seeds, forward only) and optionally a label-shuffled twin; the preserved Phase 17A C0 predictions (B0, C1, shuffled) for seed 201 as the "existing CNN baseline for context".
- Statistics: per-target AUC with 1,000-resample study-level bootstrap CIs and paired differences (D minus B0, D minus C1, D minus metadata, D minus untrained) using `mri_core/weak_label_compare.py`; checks: validation hash equals the registry, leakage report clean, checkpoint hashes, finite losses.
- Not done by the driver: any ROI model, gold scoring, test inference, submission.

## Phase 19C: AMP diagnostics, update accounting and the full Arm D driver (prepared; nothing launched)
**What the Phase 19B batch-2 "non-finite gradients" were.** In the shared trainer a non-finite gradient under AMP was already skipped by `GradScaler.step` (found-inf is recorded when the gradients are unscaled), so a bad gradient did not reach the optimizer; but this was implicit, the scale and the skips were not recorded, the non-AMP path (`optimizer.step()`) had no guard, and the scheduler/step counters knew only batches. The Phase 19B smoke itself was a hand-written loop that reported the first overflows honestly as failures; the scaler's default start scale of 65,536 plausibly overflowed fp16 during the first updates. This is consistent with, not proven by, the data (the scale was not logged).

**Changes (`mri_core/weak_label_train.py`, shared by every arm; defaults keep old behaviour):**
- Every optimizer update is guarded explicitly: after unscaling, the global gradient norm must be finite; otherwise `optimizer.step()` is never called (weights and Adam moments are untouched), the scaler lowers its scale and the update is counted as skipped. Applies to the AMP and the fp32 path.
- `update_log.jsonl`: one row per update with scale before and after, finite flag, skipped flag, number of non-finite gradient tensors, gradient norm, learning rate, applied/skipped totals and training loss; per-epoch records carry scale at start and end, applied/skipped updates and totals. `analyze_update_log` summarises it and checks that the accounting is consistent.
- Aborts, before any checkpoint is written: a non-finite loss; 20 consecutive skipped updates; a scale below 1.0 (persistent overflow, not start-up calibration).
- Gradient accumulation (`grad_accum_steps`): each micro-batch loss is divided by the size of its group, so the update uses the mean gradient; the last group of an epoch may be smaller. **Global step = optimizer updates (attempted, including skipped)**; applied/skipped counters are checkpointed; the cosine schedule stays epoch-based and advances once per epoch. Resuming with a different accumulation is refused; update-log rows of a lost epoch are trimmed on resume.
- Initial fp16 scale: `amp_init_scale` = **1024** for Arm D (library default 65,536 remains for earlier arms). Justification: the smoke overflowed at the default; a lower start costs nothing because the scaler grows back by itself. No separate warm-up phase was added: skipped steps cost nothing but time and the dynamic scaler already is the warm-up. Whether 1024 is enough must be shown by the stability rehearsal below, not assumed.

**Arm D driver (`scripts/kaggle_phase19_driver.py`):** official weights are downloaded (HTTPS, 30 s connect timeout, 300 s total, 200 MB cap, full SHA-256, fail closed; no weights dataset; random init only with `P19_RANDOM_INIT=1` in full mode). Batch 2 x accumulation 2 (effective 4), `amp_init_scale` 1024, 12 epochs, lr 1e-4, weight decay 0.05, seed 201, registered 962/238 partition (hash enforced), original B0 labels, metadata baselines and the paired comparison protocol unchanged. Checkpoints keep model, optimizer, scheduler, scaler, all RNG states, loader generator, dataset fingerprint, epoch and global step.

**Stability rehearsal (`P19_MODE=stability`, kernel folder `p19c_stability_DO_NOT_PUSH_without_approval`):** the same driver code, bounded: the first 48 registered **training** studies (asserted disjoint from the registered validation studies, gold and test), real original weak labels, pretrained trunk, AMP, batch 2 x 2, 3 epochs, cut after epoch 1 and resumed on the GPU. No validation scoring on registered data, no metadata baselines, no claim. The trainer's internal validation loss is computed on a hash-selected fraction of those same training studies. Verdict records skipped updates, skips after the first 20 updates, scale trajectory, accounting consistency, resume continuity (global step, scaler carried over), peak VRAM and epoch seconds. Expected cost: about 48 studies x 1.2 s decoding + about 6 min of training, roughly 10 min of T4 (about 0.15-0.2 GPU-h).

## Phase 19D: full pretrained Arm D run (prepared; NOT launched)
**Evidence from the Phase 19C v2 rehearsal (T4, 48 training studies, 3 epochs, cut after epoch 1 and resumed):** 24 updates applied, 0 skipped, scale stayed 1024, accounting consistent, resume restored optimizer/scheduler/scaler/RNG/counters, peak allocated 4.92 GB (reserved was not logged; 5.04 GB in the Phase 19B smoke). **Not shown by it:** (1) an AMP overflow or scale growth on the GPU (24 updates are far below the scaler's 2,000-update growth interval; the full run, about 2,890 updates, crosses it once, and a halving after an overflow there would be normal); this logic is covered by CPU tests including a resume across a growth/overflow sequence (`tests/test_phase19d_full.py`); (2) **every one of the 24 updates was clipped**: pre-clip gradient norms 6.3-75.7 (median 17.7, epoch means 19.7 / 23.5 / 26.0) against a clip of 1.0. With AdamW a constant clip factor largely cancels, but a growing norm is worth watching: the full run records `grad_clipped_fraction`, mean and max gradient norm and the scale per epoch in `final_summary.json -> run_D.per_epoch`. The clip is kept at 1.0 as specified; changing it without evidence would be an untested deviation.

**Configuration (driver defaults, full mode):** seed 201, registered partition 962 train / 238 validation (validation SHA-256 `b97c2728...`, training pool `83a416a0...`, manifest `b44de700...`; reproduced locally by `tests/test_phase19d_full.py`), original B0 weak labels (Lateral Meniscus weight 0), 12 epochs, batch 2 x accumulation 2 (effective 4, about 241 optimizer updates per epoch), AdamW lr 1e-4, weight decay 0.05, clip 1.0, FP16 AMP with initial scale 1024 and growth interval 2000, drop-path 0.1, official torchvision ConvNeXt-T downloaded over HTTPS with full SHA-256 verification (internet is on for that download only; nothing else is fetched). Gold and test studies are excluded and re-asserted (`assert_no_leakage`); no gold or test scoring happens. After training the driver scores the registered validation set against the weak labels and fits the metadata-only baselines on the same training studies (same as the Phase 19A design) so the paired comparison with the preserved Phase 17A B0/C1/shuffled predictions (`outputs/kaggle_smoke/out_p17a_seed201_v2/phase17a/`, untouched) can be done locally. Claims remain descriptive agreement with weak labels.

**Checkpoints and interruption.** `last.pt` (model, optimizer, scheduler, scaler, torch/python/numpy/CUDA/loader RNG, epoch, global step, counters, metrics history, train/validation IDs, dataset fingerprint) is written atomically after every epoch, together with `update_log.jsonl`. A time budget (`P19_MAX_SECONDS`, default 6 h; Kaggle's session limit is 9 h) pauses cleanly between epochs; the driver then writes `stage: paused`, does **no scoring** and exits. Kaggle keeps `/kaggle/working` of a version that ends by completion, timeout or error (recovered this way in earlier phases), so after any interruption: (1) `kaggle kernels output draculess/rsna-phase19d-arm-d-full -p <new folder>` to keep a local copy of `phase19/runs/s201_D/` (about 350 MB `last.pt`); (2) create a private dataset from that `s201_D` folder (or add the kernel's previous version as an input) and attach it to a new version; the driver finds exactly one `s201_D/last.pt` under the inputs (or `P19_PREV`), copies it, and the trainer resumes at the saved epoch. The trainer refuses a checkpoint whose configuration identity, target columns, accumulation factor or dataset fingerprint differ. The decode cache lives in `/tmp` and is rebuilt on resume (about 10-25 minutes).

**Expected cost (estimates from measured pieces):** training about 0.35 s per micro-batch including validation and checkpoint writes (epoch 3 of the rehearsal) means about 3-4 minutes per epoch, 40-50 minutes for 12; decoding/caching 1,200 studies at 256 px about 10-25 minutes (4.2 GB cache); scoring and baselines a few minutes. **Total about 1.0-1.3 GPU-hours** (quota left about 28 h). Peak GPU memory about 5 GB allocated of 15.6 GB. Disk: cache 4.2 GB, `last.pt` 0.35 GB, weights 0.11 GB of about 20 GB free.

**Remaining blockers:** explicit launch authorization; the torchvision weights licence is unstated (downloaded directly for research use, not redistributed); Kaggle's treatment of an internet-enabled run was accepted in Phases 19B/19C; ROI Arm E stays blocked (no ROI source).
